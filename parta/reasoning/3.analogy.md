# DSSSB TGT — Number Analogy: Complete Exam-Ready Notes

> Prepared from the supplied YouTube lecture transcript.

## 1. Analogy Basics

Analogy = Similarity = Samanta = Samaroopta.

Number analogy has the form `A : B :: C : ?`.

The lecture identifies four types: Number, Alphabet, Figure, and Word. This document focuses on Number Analogy.

## 2. Most Important Rule

Number analogy can have multiple mathematically valid relations. Therefore, do not accept the first relation you can construct. Use the options and choose the **best/direct option** according to the priority rules.

## 3. Master Priority

```text
1. Square / Cube / Powers
2. Direct Multiplication / Division
3. Addition / Subtraction
4. Digital Sum / Individual-Digit Logic
```

The lecture also discusses prime-number logic, but treats it as rare/indirect compared with the standard direct patterns.

### Golden rule

**Direct logic > indirect logic.**

## 4. Do Not Automatically Use Ratio/Proportion

For number analogy, do not automatically solve `A:B::C:x` using `A/B=C/x`. The task is to identify the intended relation/pattern.

## 5. Square Logic

Check `n²`, `n²+1`, `n²−1`, and similar direct square constructions.

Examples:

```text
5² + 1 = 26
7² + 1 = 50
5² − 1 = 24
8² − 1 = 63
```

If a number is clearly a square or is immediately above/below a square, test this before multiplication or addition.

## 6. Cube Logic

Check `n³`, `n³+1`, `n³−1`, `n³+n`, and similar direct cube constructions.

Examples:

```text
5³ − 1 = 124
6³ + 6 = 222
7³ + 7 = 350
```

Important cubes: `1, 8, 27, 64, 125, 216, 343, 512, 729, 1000`.

## 7. Powers

The lecture treats powers as part of square/cube logic. Check `n⁴`, `n⁵`, etc. when the sequence supports them.

For `1`, remember that `1²=1³=1⁴=...=1`; determine its exponent from the surrounding pattern.

## 8. Consecutive Bases

When using powers, check the underlying bases. A pattern such as `5²+1, 6²+1, 7²+1, 8²+1` is stronger than an option that breaks the consecutive-base sequence.

## 9. Multiplication

If no direct square/cube/power relation works, test direct multiplication: `×2, ×3, ×4, ×5, ×1.5, ×3.5`, etc.

If several multiplication constructions work, prefer the direct/simple multiplication.

Example:

```text
16 × 3.5 = 56
```

The lecture notes that `3.5×n = 3n + 0.5n = 4n − 0.5n`.

## 10. Division

If the number decreases and no stronger power pattern exists, test division.

Quick filter:

```text
Increase → multiplication may fit
Decrease → division may fit
```

But this is only a filter; square/cube/power priority still comes first.

## 11. Half / Double / ±1 Patterns

Examples from the lecture:

```text
20 ÷ 2 + 1 = 11
102 ÷ 2 + 1 = 52
42 ÷ 2 − 1 = 20
64 ÷ 2 − 1 = 31
```

Do not choose these if a higher-priority direct power relation exists.

## 12. Addition and Subtraction

After power and multiplication/division checks, test direct `+` and `−` relations, including constant differences.

Example:

```text
8 → 19 → 30
Differences = 11, 11
```

## 13. Digital Sum

Digital sum is a fallback. Use it when square/cube, multiplication/division, and addition/subtraction do not explain the options.

Example:

```text
56 → 5 + 6 = 11
```

Follow the convention stated in the actual question; do not invent a digital-sum rule.

## 14. Individual-Digit Logic

Sometimes the relationship is applied separately to digits. Use this only after the standard whole-number patterns fail or the options clearly require it.

The lecture demonstrates digit-wise operations in which digits are combined, multiplied, added, or otherwise transformed.

## 15. Four-Digit Questions

For four-digit questions, if the standard patterns do not fit, move to addition/subtraction and then digital-sum or individual-digit analysis.

## 16. Prime-Number Logic

Prime-number patterns can be valid, including successive primes such as `2,3,5,7,11,13,17,...`, but the lecture treats prime logic as rare/indirect.

Do not use an indirect prime interpretation to defeat a clear direct square/cube/power relation.

Also verify that the primes are actually successive; e.g. `13→17` is successive, while `13→19` skips 17.

## 17. Best-Option Strategy

Ask: **Which option follows the strongest, most direct intended relation?**

Use this order:

```text
Power → Multiply/Divide → Add/Subtract → Digital/Digits
```

If a square/cube relation is established, stop looking for multiplication, division, addition, subtraction, or digital sum merely because those can produce other values.

## 18. Direct vs Indirect

Direct: `4²+1`, `8×3`, `30−11`.

Indirect: using an extra idea such as “the next prime after 7 is 11.”

**Direct gets priority.**

## 19. When Two Options Both Fit

Check:

1. Which relation is direct?

2. Are the bases consecutive?

3. Is the operation consistent across every given pair?

4. Which option is actually present?

5. Is one relation unnecessarily complicated?

If two power relations remain genuinely indistinguishable, do not invent a fake rule just to force uniqueness; the options may be ambiguous.

## 20. Option-Based Elimination

Options are essential in number analogy. If a theoretically possible result is absent, move to the next valid pattern and check the available choices.

## 21. Common Traps

- Choosing the first possible relation.

- Using ratio/proportion automatically.

- Choosing multiplication before checking squares/cubes.

- Overusing prime logic.

- Applying digital sum too early.

- Ignoring consecutive base numbers.

- Ignoring the answer options.

- Continuing to search after a strong direct relation is confirmed.

## 22. Fast Exam Algorithm

```text
Read all options
↓
Square?
↓
Cube?
↓
Other power?
↓
Direct × or ÷?
↓
Direct + or −?
↓
Digital sum / individual digits?
↓
Rare/indirect logic only if needed
↓
Direct > indirect
↓
Choose best option
```

## 25. Worked Examples

### Example A — Square + 1

`5 → 26` because `5²+1=26`. Therefore `7 → 50` under the same rule.

### Example B — Cube − 1

`5 → 124` because `5³−1=124`. Therefore `7 → 342`.

### Example C — Cube + Number

`6 → 222` because `6³+6=216+6=222`. Therefore `7 → 350`.

### Example D — Division

`56 → 8` using `÷7`; then `98 → 14` if the options support the same direct relation.

### Example E — Half + 1

`20 → 11` using `20÷2+1`; therefore `102 → 52`.
